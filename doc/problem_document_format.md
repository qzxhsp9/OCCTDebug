# OCCTDebug Problem Markdown Format

This document defines the user-authored problem document consumed by `ProblemDocumentImporter`.
The same format is generated by **File -> Create problem document...** and imported by
**File -> Import problem document...**.
The tool is organized around one problem at a time; the main window shows the current problem
title, category and input count above the geometry views.

## Why the unit test exists

`tests/problem_document_importer.cpp` is a contract test for the problem intake format.
It protects the path from a handwritten Markdown case to structured analysis data:

- title, category, OCCT version, compiler and build type are parsed into `ProblemContext`;
- input BREP/STEP file paths are preserved for later reproduction;
- expected and actual behavior are preserved as evidence fields;
- reproduction steps and notes are stored for later report generation;
- custom environment parameters such as `FuzzyValue: 0.01` are not discarded;
- a generated template can be parsed back without losing the important fields.

This matters because AI-driven analysis should not start from free text only. The tool needs a
stable, testable intake document that can become a reproducible session, evidence bundle and report.

## Template

```markdown
# Boolean half-space shell cut

## Summary

Shell cut by half-space produces no cap face.

## Environment

- Category: Boolean
- OCCT Version: 7.9.3
- Compiler: MSVC 19.39
- Build Type: Debug
- FuzzyValue: 0.01

## Input Files

- case/input.brep
- case/tool.step

## Reproduction Steps

1. Load input shell.
2. Run BRepAlgoAPI_Cut with half-space tool.

## Expected Behavior

Result status: has a section cap face.

## Actual Behavior

Observed result: remains an open shell.

## Notes / Suspected Area

Likely BOPAlgo behavior for sheet bodies.
```

## Supported Fields

Required by convention:

- `# <title>`: short problem title.
- `## Summary`: concise symptom description.
- `## Environment`: structured key-value metadata.
- `## Input Files`: one input path per line. Relative paths are resolved against the Markdown file when imported from the UI.
  Multiple BREP/STEP files are loaded into the current problem view as one OCCT compound, so the
  shape tree, viewer and diagnostic rules see every listed model input.
- `## Reproduction Steps`: ordered or unordered reproduction steps.
- `## Expected Behavior`: what should happen.
- `## Actual Behavior`: what actually happens.
- `## Notes / Suspected Area`: optional human analysis or suspected OCCT component.

Recognized environment keys:

- `Category`: `Unknown`, `Boolean`, `Projection`, `Classification`, `Topology`, `Tolerance`, `Meshing`, `HLR`, `Performance`, `Crash`.
- `OCCT Version`
- `Compiler`
- `Build Type`

Any other `Key: Value` line in `Environment` is preserved in `ProblemContext.parameters`.
The template dialog exposes these extra fields through **Custom properties -> Add property**.
